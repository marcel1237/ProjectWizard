Visão geral

O aplicativo principal organiza criação, abertura e trabalho em projetos. A interface reúne editor com realce de sintaxe, explorador de pacotes, terminal, Git, backups, preferências, dashboards e painéis auxiliares. Serviços de persistência e backup protegem o estado local; o ciclo de vida central encerra processos e executores ao trocar ou fechar projetos.

O repositório contém dois builds Maven independentes: a IDE na raiz e a biblioteca/gerador em cloudwizard/. O script build-all.sh valida ambos.

Cloud Wizard

Produto proprietário, comercial e pago, regido por licença separada. O domínio declara a intenção por anotações. O leitor produz um modelo independente de fornecedor; o motor de regras resolve cada capability usando adaptadores registrados pela SPI do Java. O resultado é um ResolutionPlan.

anotações → modelo unificado → rules engine → AWS | Google | Azure | OCI | IBM | Alibaba | Tencent | Huawei | Yandex

Modelo de negócios

As nove clouds públicas oficiais formam a única matriz de referência mantida pelo produto. Outros nomes permanecem apenas no catálogo de descoberta, sem avaliação ativa. O documento MODELO_NEGOCIOS.md descreve planos, receitas, Provider Adapter Kit, OEM, marketplace e estados Community, Verified e Certified.

Build, execução e qualidade

# Validar os dois projetos e atualizar os Javadocs
./build-all.sh

# Executar a IDE
mvn clean javafx:run

# Gerar projeto pelo Cloud Wizard
java -jar cloudwizard/target/cloudwizard-0.1.0-SNAPSHOT.jar \
  /diretorio/de/saida meu-projeto cloud-native-full

O Maven usa Java 21, JUnit Jupiter, Surefire e JaCoCo. O pacote principal é criado em target/ProjectWizard-1.0.0.jar. Diretórios target são produtos de build e não precisam ser versionados.

Limites e próximos passos

  • Adicionar provisionadores como consumidores do plano resolvido, preservando o núcleo neutro.
  • Ampliar testes JavaFX para fluxos completos e processos externos.
  • Produzir distribuição nativa autocontida com jpackage.
  • Evoluir equivalências com regras semânticas: IAM, filas e bancos têm modelos diferentes entre fornecedores e não são intercambiáveis apenas pelo nome.

Catálogo de providers

Um asset reúne 88 nomes em formato CSV. Somente AWS, Google Cloud, Microsoft Azure, Oracle Cloud, IBM Cloud, Alibaba Cloud, Tencent Cloud, Huawei Cloud e Yandex Cloud são referências oficiais OFFICIAL_CORE. Todos os demais estão como DISCOVERY_ASSET, not-assessed e REQUIRES_VALIDATION, sem equivalência atribuída.

Providers oficiais asiáticos e eurasiático

A matriz operacional complementar registra Alibaba Cloud, Tencent Cloud, Huawei Cloud e Yandex Cloud com dezesseis capabilities, adapters, SPI e testes. A Yandex exige análise contínua de sanções, pagamentos, legislação e residência de dados.
